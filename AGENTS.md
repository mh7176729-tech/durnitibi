# Project Rules and Guidelines

## 1. Strict Scope Discipline & Change Boundaries
- Modify ONLY the specific component, feature, or code that the user explicitly asks to change.
- Never refactor, redesign, or touch unrelated pages, layouts, components, or styles without explicit user request.
- Treat the user's prompt as the exact boundary of work: do not add unrequested features or redesign existing sections.

## 2. User Data & Published News Preservation
- NEVER overwrite, wipe, reset, or alter user-published news, drafts, categories, ads, or settings in localStorage or any database.
- Any default/seed data must only serve as fallback when storage is completely empty. User-created items must always be preserved and prioritized.
- Never change the structure of existing published news articles or their IDs.
